# 用户已确认需求

本文件保留接手所需范围，不替换 SOURCE_AUDIT.md 中的真实源码事实。

## 环境与轮换

- 两台有 root 的公网 Debian 13，均安装 jieshu，各自经已有 WireGuard 连接同一 NAT 机。
- 当前生产机有 443 主节点、普通 VLESS 临时节点和 WG-NAT 临时节点；备用机只有自己的 443，无临时用户节点。仍须实际检查是否为空和端口冲突。
- 备用机用另一个备用域名完成原安装检查；迁入用户保留原业务域名，不能被备用域名替换。
- 用户节点全部 IPv4，业务域名只有 A 记录，没有 AAAA；不用设计 IPv6 迁移。
- 用户在服务器供应商额度耗尽前主动迁移，源仍能 SSH/读文件/传数据。目标相应端口未占用，安全组允许放行。
- 每轮迁全部当前临时用户节点及最新状态；方向任意。用户确认接管后自己重装旧机，使其成为空备用机，再反向轮换。
- 接管后仍可用原 jieshu 命令新增节点，域名由用户设置；下一轮同时迁旧、新节点，不修改原创建命令的默认域名。

## 链接与用户状态

- 不要求真实用户更换链接、重新导入或更新订阅。逐节点保留业务域名、端口、UUID、Reality 私钥/公钥、Short ID、SNI、flow 等协议参数，原名称、ID/TAG 和 OWNER 关系。
- 不同轮次和不同节点可能各有不同 Reality 密钥；禁止用主节点的一套密钥覆盖全部。
- 普通节点继续直出，NAT 节点继续使用目标已有 WG；不得重建用户导致新 UUID、新端口、新期限。
- 总配额、已用量、余额、创建/到期时间、周期与下次重置、IP 数量及超时、已配限速、暂停/禁用/封禁都要接续。
- 例：100 GiB 总额、已用 60 GiB，迁入余 40 GiB；再用 10 GiB 后下一轮已用 70、余 30。供应商额度不等于用户配额。
- 已耗尽/禁用不能因迁移复活；到期不能延期。迁移期间遇原周期正常重置/到期，遵循原规则，不额外重置或延期。

## 交接流程

1. 默认当前生产机运行，填写目标真实公网 IP、SSH 端口，用正常 root SSH 认证，不硬编码密码/密钥，不依赖业务域名管理连接。
2. 只读预检两机、SSH、实际安装版本、端口、依赖；提前准备目标以缩短暂停。
3. 最终冻结源用户流量，协调 ExecStopPost、watchdog、GC、quota save/reset/expiry 等写入，结算真实最终用量，生成一致快照。
4. 通过 SSH 传输，目标先恢复防护，再验证配置、认证参数、监听和状态，最后开放。
5. 明确何时可以由用户手改业务 DNS A 记录；DNS 缓存不应让源继续提供另一份余额。
6. 用户用原链接外部验证后自行重装旧机；工具不自动重装，也不在验证完成前销毁源恢复材料。

允许暂停旧节点及 TCP 重连，不要求活 TCP 无缝搬迁。优先准确余额、原链接、限制接续。

## 边界与失败

- 不迁 443、主节点链接、默认发布域名；但临时节点依赖的旧 Reality 私钥必须逐个保留。
- 不迁/重建/覆盖目标 WG；不操作 NAT 机、不检测/比较 NAT 出口公网 IP。仅检查节点所需本机 WG 接口、mark、路由、服务，匹配则沿用，不匹配明确报错。
- 不做整机克隆、日志平台、供应商流量监控、自动 DNS、长期双机同步。
- 不把内核计数读取失败当零；不复制环境绑定的完整 nft/tc 规则；不 flush 全机防火墙/网卡限速。
- 暂停不能触发误删、自动拉起或额外重置。未知残留、冲突、无法恢复的配置必须报错，不换端口或覆盖未知数据。
- 重试不重复导入/发配额，不得用旧快照覆盖已开放目标的新用量。若目标已服务，回退必须处理新增用量，实际应从它生成新快照迁移。
- 运行包含凭据，限 root 权限，不进入本公开仓库或普通日志。

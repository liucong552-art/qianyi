# 中断后恢复及进度接续

## 开发进度

代码、源码审计、测试、本文档和 PROGRESS.md 均在 qianyi 仓库。重新开始开发时先拉取仓库、读 PROGRESS.md、查看最近提交和测试结果。不要依赖之前聊天里的临时路径或未提交副本。

## 运行事务

运行进度在两台服务器各自的 `/var/lib/qianyi/sessions/事务编号/`。`state.json` 包含角色/阶段/目标身份；`settlement.json` 是源最终结算的写前记录；`snapshot.json` 是封存快照；源成功交接后的 `originals/` 保留迁走的原文件。所有这些都是私密资料。

先执行：

```bash
python3 /usr/local/lib/qianyi/agent.py status
systemctl status qianyi-transfer-事务编号.service --no-pager
journalctl -u qianyi-transfer-事务编号.service -n 30 --no-pager
```

程序错误不打印链接、私钥或完整配置。不要为排查方便把 state/snapshot 内容直接发到公共仓库。

## 常见情况

**本地终端断开：** 交接任务由 systemd 继续执行。重新登录源真实 IP，先 status；若已 RETIRED，按正常流程验收。若失败，修复报错原因后 resume。

**SSH 身份核验失败：** 在源机用目标 IP 正常 SSH，核对主机密钥、root 认证、端口/防火墙。新装服务器的新密钥需要人工验证，不能改成 StrictHostKeyChecking=no。再 resume 原事务。

**预检版本哈希不匹配：** 这是不受支持的安装版本。保存脱敏的错误路径和实际程序 SHA，审计对应源码后增加适配；不要直接更改 compatibility.json 或重新安装生产节点来“通过”。

**后台短任务未自然结束：** 工具不会强杀配额写入。检查该服务是否仍在执行、是否有管理/安装进程占锁。不要清空锁文件；解决原因后 resume。

**发现预检后节点配置/集合发生变化：** 不把准备时的旧数据盖回生产文件。保留维护状态和所有文件，检查是否有人在维护窗口调用管理命令。此版对无法证明一致的并发变更失败关闭；不要直接删状态解除冻结。应依据当前文件、已落盘结算意图和内核计数完成专项恢复后重新开始。

**源冻结前计数已缺失，或者结算前突然掉电：** 工具不能推算未保存的内核用量。不能把它视为零，不能直接放行目标。需要你已有的可信计量/系统恢复依据，或修复原环境后重新核查；工具保留数据并停止。没有依据时不会假装余额准确。

**目标导入到一半失败：** 保持源关闭。相同事务 resume 会检查文件写入归属、摘要和阶段，继续恢复；未知数据被修改时拒绝覆盖。修复必要依赖，不要运行新建节点命令代替迁移。

**OPEN_UNCERTAIN：** 即使 SSH 没收到成功回复，目标也可能已经服务。resume 先查询目标；如果目标 OPEN，只完成放行/退休收尾，不重新导入。无法确认时保持源冻结。

**OPEN 前协调取消：** 等 worker 已停止后，在源执行 abort。程序先让目标永久记录 ABORTED 并确认无监听，再恢复源。被撤销的目标保留隔离资料与部分导入，不自动清理。最简单的空备用机恢复办法是你确认源已 RESUMED 后自行重装目标并重新安装 jieshu/WG；不是重装仍在生产的源机。

**OPEN 后需要回退：** 旧快照已过期。必须在新生产机读取最新节点、结算新增流量，以新事务迁往一个经过检查的空备用机。旧源尚未重装、还有原迁移残留时不能直接作为空目标。工具没有“强制恢复旧余额”开关。

**目标重启后失败：** 保留目标最新用户状态与计数；查看 qianyi-boot、vless-managed-restore、portbw-restore 和相应节点服务。门禁会阻止没有防护的节点启动。修复原环境，不能拿源旧快照覆盖目标。

## 不应手工做的恢复动作

- 不删除 `/var/lib/qianyi/maintenance`、holds、事务状态或 systemd 覆盖来强行上线；它们用于防止双份余额和清理钩子误删。
- 不复制旧 quota `.env` 覆盖已服务目标。
- 不运行 `pq_add.sh`、重新创建 UUID 或清零计数冒充迁移恢复。
- 不清空全机 nftables 或网卡 qdisc。
- 不在目标真实连接未验收前重装源机。

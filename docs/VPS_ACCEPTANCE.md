# 真实 Debian 13 VPS 验收

**本清单尚未在真实 VPS 执行，所有下列用例均待验收。** 本地 73 项测试及提交 `1c40cc0` 的 [隔离 CI](https://github.com/liucong552-art/qianyi/actions/runs/42238894007) 已通过真实 quota/IP/nft、portbw/tc、固定 Xray Reality 烟测；这些不等同于两台真实服务器的完整迁移。最新自动化证据见 [TESTING.md](TESTING.md)。

## 环境

准备两台测试 Debian 13，均有已支持版本 jieshu / Xray / WG；目标只有 443。准备第三台外部客户端。使用两机自己的现成 WG；不检查 NAT 出口公网 IP，不改 NAT 机。

记录两机 443 配置、主节点状态和 `/etc/wireguard/` 文件摘要。建立普通及 NAT 测试节点，尽量覆盖以下矩阵：

| 测试用户 | 需要的数据 |
|---|---|
| 普通节点 1 | 业务域名甲、独立 UUID/端口、配额、IP_LIMIT=2、超时 120 秒 |
| NAT 节点 2 | 业务域名乙、WG 元组、与节点 1 不同的 Reality 密钥 |
| 普通节点 3 | 无配额 / IP_LIMIT=0，仍有 IPv4 family guard |
| 耗尽节点 | SAVED_USED + live 达到总额，不能重新连接使用 |
| 暂停节点 | 使用标准 pause_vless_PORT 封禁 |
| 黑名单节点 | 单 IPv4 和 CIDR，验证受封来源失败、其他来源成功 |
| 静态限速节点 | 分别测上传与下载，不只是看记录 |
| 自动限速节点 | 在 hold / cooldown 中迁移，核对剩余保护时间 |
| 临近到期 / 重置节点 | 用测试夹具安排有效期/重置边界，保持原字段关系；不能改生产数据 |

## 正常交接

1. 外部客户端使用原链接建立普通和 NAT 连接并产生可测量流量。记录配额总额、持久用量、named quota.used、入/出 named counter、到期和下次重置 epoch。
2. 执行只读 preflight，对比之前的业务文件和 nft/tc 对象：不能发生重建、清零或停服务。核对 source/target machine-id 与 Xray 版本。
3. prepare 后新增一个不同密钥的临时节点并修改一个测试用户的限制。cutover 必须发现最新状态。
4. 在持续传输中 cutover，证明源所有用户端口被阻断且停止监听；确认其 443 仍保持原配置和服务。监测冻结以后源用户计数不继续增长。
5. 目标 READY 时由观测端确认其用户端口仍被 fence 阻断；quota、IP、pause/ban、portbw 必须先存在。服务可以监听，但用户尚不能绕过屏障。
6. 目标 OPEN / 源 RETIRED 后，在外部客户端仅覆盖业务域名解析到目标 IP，保持**原链接**测试两个节点类型。然后修改公共 DNS A 记录。不要靠更新订阅重新生成链接来掩盖认证变化。
7. 对比源快照和目标配置/URL 原文与摘要；验证不同节点各自 PBK 与私钥配对，业务域名未变成备用域名。正常测试新增流量应计入目标余额。
8. 验证 100 GiB / 60 GiB 的测试余额迁后为 40 GiB，正常消耗后按实际字节扣减；耗尽、暂停、禁用、封禁节点不能因为迁移恢复使用。
9. 正常重启目标。用原链接重连；检查所有存活临时节点、防护、动态 IP 上限、黑名单、静态及自动限速、周期和到期。核对 443/WG 文件摘要没有变化。

## 故障与重复执行

只在测试 VPS 测试，所有恢复动作优先使用 status/resume/abort。

| 注入点 | 必须观察到的结果 |
|---|---|
| 预检时目标占用一个用户端口或放入孤立 .env | 在源停流前报错，不换端口、不覆盖 |
| 目标 WG_IF/MARK/路由元组不匹配 | 只读报错，不调用 wg_nat_guard/healthcheck 修复 |
| 源 live quota/counter 缺失或 nft 查询失败 | 不生成假零快照，不放行目标 |
| 源结算意图落盘后中止 worker | resume 使用同一结算意图；不重复叠加旧内核计数 |
| 目标写入部分文件后断开 SSH | 源保持冻结；resume 完成同一事务，没有重复节点 |
| 目标 READY 后进程退出 | 重试启动/验证，不重新导入余额 |
| READY 中部分节点自然到期，原 ExecStopPost/GC 删除文件后重启 | 从源 resume；只恢复存活节点当前余额；到期节点不补文件/延长/重建限速，verify 报 expired |
| READY 中全部节点自然到期且文件已删除 | 可完成空存活集验证；不启动或重建任何到期节点 |
| READY 中未到期节点的必要文件缺失，或到期端口仍有监听 | 明确拒绝并保留屏障；不能以“到期清理”掩盖有效节点丢失或残留进程 |
| READY 重置已写入持久文件，恢复中断再重试 | 从目标当前 NEXT_RESET/余额继续；不得按旧快照再发配额 |
| 目标已写 OPEN，但回复在网络中丢失 | 源 OPEN_UNCERTAIN；resume 查询并完成，不能 abort 旧余额 |
| OPEN 后再发送旧 stage 请求 | 明确拒绝；目标新增用量保持 |
| 源/目标在维护中重启 | 屏障/门禁不放行双份余额；计数无依据时失败关闭 |
| OPEN 前执行 abort | 先证明目标作废并停止监听，再恢复源最终余额 |
| 源已 RESUMED，分别在放行前、放行且已有新增流量后中断 | resume 仅本机收尾；不需要目标 SSH；持久用量及实时计数不得回退/清零 |
| RESUMED 后原 GC 清理部分/全部到期节点，再 resume | 正确跳过已到期且无服务/监听节点；存活节点仍完整验证 |
| RESUMED 重试时未到期节点的 live quota/counter 缺失 | 停止，不以旧快照或假零计数恢复 |
| watchdog 持 temp.lock 等 restart，同时触发迁入节点 gate | 无父子死锁；gate 取得后续防护锁；失败不能关闭原锁或绕过门禁 |
| GC/quota save/reset 与 verify/RESUMED 收尾并发 | 原生锁覆盖元数据读取及防护验证，不能读到半套状态；systemctl start 在锁外 |
| 节点在验证到启动的间隙到期 | 门禁/原 timeout 遵守原期限；重试不得延期或复活 |
| OPEN 后执行 abort | 拒绝；必须基于目标新状态迁移 |

## 反向和多轮

1. 目标成为生产机后继续用原 jieshu 命令新建普通/NAT 节点，选择第三套 Reality 密钥与新的业务域名。
2. 在它上面继续产生用量；原测试用户累计 70 GiB 时，剩余应为 30 GiB（周期未重置）。
3. 手工重装旧机并安装 jieshu/WG，使其成为空备用机。
4. 从当前生产机发起**新事务**迁回，验证所有旧/新节点分别保留各自凭据、日期、限制和最新余额。
5. 再轮换一次。每轮只有当前生产机可提供用户余额；前一轮快照不能覆盖本轮新状态。
